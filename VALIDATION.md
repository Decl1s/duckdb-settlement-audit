# Что я фактически проверил

01.11.2026, версия 0.1.0. Локально: Linux, CPython 3.14.4, DuckDB 2.0.0,
uv 0.13.1, отдельная .venv с одним runtime distribution. Я установил зависимости
из requirements.lock с проверкой SHA; дополнительных Python-пакетов DuckDB не потребовал.

Я выполнил `python -m unittest discover -s tests -v`: **20 tests, OK**.
Я проверил ожидаемые статусы и отдельные суммы RUB/USD; split payment без
размножения заказа; replay/conflict; возвраты; валютный mismatch; free order;
точную границу допуска и даты; отсутствие пары при большом допуске; negative/zero
orphan net; независимый oracle на 70 заказах/200 платежах с перемешиванием;
некорректные суммы/даты/валюты/CSV; лимиты; большие целые; пустой typed Parquet;
повтор в новый каталог, сохранение занятого результата, checksum corruption;
уборку после failpoint и сохранение чужого lock.

В `scripts/ci.py` я дополнительно проверяю настоящий CLI и JSON, prepare без
перезаписи, 9 строк/7 issues, одинаковый логический replay, отказ при занятом
--out, отсутствие опубликованного результата после failpoint, пять упражнений
и два одинаковых source ZIP. Результат фактического полного запуска я фиксирую
в журнале выпуска; скрипт завершится ненулевым кодом при любом несовпадении.

Полный локальный `scripts/ci.py` завершился успешно: 20 tests, 5 упражнений,
CLI/replay/failpoint и 27 файлов в повторяемом ZIP.

Первый удалённый запуск 41315614661/41315621966 GitHub отклонил до создания jobs:
YAML syntax error, line 30. Я перенёс pip-команду с `:all:` в блок `run: |`;
предметный код сохранил. Релиз при этом не создавался.

Run 41315789394: Linux success; Windows прошёл 20 unit и CLI/5 заданий,
но package gate отклонил CRLF в workflow после checkout. Release skipped.
Я добавил `.gitattributes` с `* text eol=lf`, сохранив строгую проверку CR.
Теперь allowlist содержит 28 исходников.

На первом локальном прогоне предметных ошибок я не обнаружил. uv сообщил
о переходе с hardlink на copy между файловыми системами; установка завершилась
успешно. Ошибку разработки ради истории я не придумываю.

Удалённые проверки я запускаю workflow `.github/workflows/check.yml` и читаю
в [Actions](https://github.com/Decl1s/duckdb-settlement-audit/actions).
Только успешные Linux и Windows разрешают отдельный release job. Конкретный
run, исходный SHA, публичность, дерево исходников, tag, скачанный ZIP/SHA и календарь
я подтверждаю после выполнения в журнале серии; текущий текст не подменяет логи.

Я не проверял macOS, нагрузочный предел, GUI VS Code, kill/power-loss durability,
сетевой диск и враждебные filesystem races. Мой lock координирует экземпляры
моей программы. Failpoint — обычное исключение перед publish, а не имитация
отключения питания. SHA-256 не является подписью; manifest не аутентифицирован.
Я не реализовал FX, комиссии, банковские статусы, связь refund→capture,
incremental processing и ledger для аудита реальных денег.
