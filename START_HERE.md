# Как я читаю и меняю проект

Я сначала выполняю четыре команды из README, открываю CSV и summary, затем иду
по пути данных. В VS Code я открываю именно эту папку и выбираю Python из .venv.
Через Terminal → Run Task я получаю четыре задачи из `.vscode/tasks.json`.
Расширение Python для VS Code необязательно для CLI; GUI IDE я отдельно не проверял.

| Файл | Что я здесь делаю | Что я меняю под свою задачу |
| --- | --- | --- |
| settlement/examples.py | Создаю 8 заказов/10 строк платежей | Я меняю синтетический бизнес-пример; prepare пишет только в новую папку |
| settlement/contracts.py | Читаю ограниченный bytes-снимок, проверяю поля, дубли и SHA | Я добавляю поле одновременно в header, parser и SQL schema |
| sql/reconcile.sql | Отсекаю будущее, агрегирую, соединяю, назначаю status | Я меняю предметное правило; это главное место для изучения SQL |
| settlement/engine.py | Передаю typed tuples в DuckDB, сохраняю отчёты, stage/lock/rename | Я добавляю колонку в обе явные схемы и сверяю read-back |
| settlement/__main__.py | Описываю параметры CLI и exit codes | Я добавляю настройку и передаю её дальше, не прячу правило в CLI |
| tests/test_settlement.py | Проверяю правила и отказы | Я добавляю ожидание на бизнес-пример, а не копию вычисления |
| scripts/ci.py | Выполняю demo, 5 изменений, unit, ZIP | Я сверяю ручные задания с автоматическими числовыми ожиданиями |
| scripts/package_release.py | Проверяю allowlist и собираю ZIP | Я меняю PUBLIC_FILES при добавлении разрешённого исходника |
| scripts/publish_release.py | Публикую архив только из Actions main | Я не использую этот скрипт для локального доступа к аккаунту |

Я ставлю breakpoint перед `con.execute(sql, ...)`, смотрю `orders`, `payments`,
`day`, `tolerance`. Затем я сравниваю O100/O200/O500 с CTE в SQL. Для чтения
сохранённой таблицы в Python я использую DuckDB `read_parquet` из `inspect`.

| Аргумент | Для чего я его задаю |
| --- | --- |
| --orders / --payments | Я указываю два исходных CSV; в JSON я не публикую локальные пути |
| --as-of | Я фиксирую включительную календарную дату для обоих источников |
| --tolerance-minor | Я задаю допустимый модуль delta, по умолчанию 0 |
| --out | Я выбираю новый каталог результата; старый отчёт сохраняю |
| --fail-before-publish | Я демонстрирую управляемый отказ после записи и read-back, до rename |

Мои пять изменений и ответы находятся в конце [NOTES](NOTES.md). Для каждого
я копирую входы в отдельную папку и задаю новый --out; релизные исходники я не правлю
ради простого эксперимента. Настоящие данные я не добавляю в Git.
